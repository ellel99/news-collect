## 1. 目标

建立可在本地和 Docker Compose 中启动、测试、迁移和健康检查的 Python 项目骨架，为后续 Source Registry 与采集功能提供稳定基础。

## 2. 背景

这是第一个实现 SPEC。它不接入真实新闻或 X，不发送真实 Telegram 消息，不实现 AI、Event 或 Portfolio。完成后项目必须具备一致的开发、测试、配置、数据库和任务运行方式。

## 3. 前置条件与依赖

- Foundation v2.1-FROZEN 已冻结；
- 本机支持 Docker Desktop 或兼容 Docker Compose；
- Python 3.12；
- 不需要外部媒体、X 或 Telegram 权限。

## 4. 技术基线

- Python 3.12；
- `src/` 布局；
- FastAPI；
- Pydantic Settings；
- SQLAlchemy 2.x；
- Alembic；
- PostgreSQL 16；
- Redis 7；
- Celery 5 与 Celery Beat；
- `httpx`；
- pytest 与 pytest-asyncio；
- Ruff；
- mypy；
- Docker Compose；
- 依赖使用 `pyproject.toml` 管理，并生成可复现锁文件。

`uv` 是本 SPEC 固定依赖与锁文件工具；不同时维护 Poetry、Pipenv 或第二套锁文件。替换需先新增 Decision 和新 SPEC。

## 5. Foundation 与阶段边界

本 SPEC 不修改 Foundation。不得创建 Source、ContentItem、Notification、Event、Portfolio 或 Investment Plan，不接真实来源，不发送 Telegram。

## 7. 功能需求

### FR-01 应用启动

FastAPI 应用可在本地与容器启动，应用导入不得建立外部网络连接。

### FR-02 配置

配置来自环境变量，提供安全 `.env.example`。缺少生产必需配置时快速失败，测试配置可独立运行。

### FR-03 数据库

应用可连接 PostgreSQL；Alembic 可升级至 head，并可回滚本 SPEC 的迁移。

### FR-04 Redis

应用和 Celery 可连接 Redis；连接失败在 readiness 中可见。

### FR-05 健康检查

- `/health/live` 只证明进程存活；
- `/health/ready` 检查数据库和 Redis，并返回结构化组件状态；
- readiness 不泄露连接串或秘密。

### FR-06 Worker

Celery worker 可启动并执行一个无外部副作用的健康任务；Beat 可启动但不创建业务采集计划。

### FR-07 质量

Ruff、mypy、pytest 必须有统一命令并通过。

### FR-08 文档

README 说明环境要求、启动、迁移、测试、停止和常见错误。

## 8. 非功能需求

- 默认日志不输出密码、Token 或完整数据库 URL；
- 容器使用非 root 用户（数据库官方镜像除外）；
- 健康检查有超时；
- 导入应用不依赖网络；
- 测试不调用真实外部服务；
- 服务名、端口和卷清晰且可配置；
- 所有时间使用 UTC。

## 13. 错误处理

| Error Code | 条件 | 是否重试 | 表现 |
|---|---|---|---|
| `CONFIG_INVALID` | 配置缺失或非法 | 否 | 启动失败并给出字段名 |
| `DB_UNAVAILABLE` | 数据库不可用 | 是 | readiness 失败 |
| `REDIS_UNAVAILABLE` | Redis 不可用 | 是 | readiness 失败 |
| `TASK_FAILED` | 健康任务异常 | 视原因 | worker 记录脱敏错误 |

## 14. Migration and Rollback

- `alembic upgrade head` 成功；
- `alembic downgrade -1` 成功；
- 再次 upgrade 成功；
- 回滚前对任何已有本地数据明确警告；
- 不删除用户目录或宽泛数据路径。
