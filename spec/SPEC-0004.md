# SPEC-0004 — First Approved Polling Source Pilot

状态：Active — Docs Review（implementation not started）

## 1. 目标

定义第一个合法、低成本或公开 Polling Source Pilot 的实现合同，为后续真实来源接入提供
provider-neutral 模板。本 SPEC 的文档进入审核不代表实现授权；具体首个 provider 必须由
用户在本文档审核中明确确认，且本文档 Review PASS 后才可开始实现。

未来实现必须验证：

- SPEC-0003 collection framework 能接入一个经批准的真实 polling source；
- 既有 `Source`、`SourceAccount`、`CollectionCursor`、`CollectionRun`、`RawItem` 能正确
  承载真实来源运行；
- cursor、watermark、retry、idempotency、有限 backfill 和 access policy 合同可执行；
- downstream 只依赖统一内部 envelope，不依赖 provider SDK 或 raw payload；
- 无 schema 变化，且不实现 downstream normalization、dedup、outbox、AI 或 Event。

## 2. 背景

SPEC-0003 已完成并通过 fake adapter 验证来源无关采集框架。下一步只能选择一个合法来源，
以最小范围证明真实 Polling 接入，同时保持 `Source Adapter / Connector → 统一 envelope →
现有 collection runner` 边界。

PR #6 记录了长期 provider-neutral 架构方向。SPEC-0004 只采用与当前 Phase 1 一致的
Polling adapter 边界，不批准 Streaming、Webhook、通用 Historical Backfill、Internal
Event Bus、Event、AI、Market Validation 或 Research Recommendation。

## 8. 功能需求

### FR-01 — Approved Single Polling Source

要求：实现只允许一个由用户明确批准的合法 Polling Source。Source 必须 enabled，
`authorization_status` 为 `authorized` 或 `implemented`，且使用本 SPEC 注册的 adapter key。

验收方式：配置和调度测试证明只有获批 Source/SourceAccount 可运行；其他 provider、未知 key、
未授权状态和第二来源均 fail closed，不产生 CollectionRun 或网络请求。

### FR-02 — Provider-Neutral Adapter Boundary

要求：Source Adapter / Connector 负责认证读取、provider-specific mapping 和错误翻译。
它只能返回统一 `RawItemEnvelope` / `FetchBatch`，不得写数据库、推进 cursor、调度 retry、
发送通知或调用 downstream。

Downstream 不得导入 provider SDK，不得读取 provider raw payload 专有字段。provider parser
不得扩散到 normalization、dedup、outbox、Event 或 AI。

验收方式：adapter contract test、依赖扫描和模块边界测试证明 provider 代码只存在于 adapter
边界，runner 与 downstream 只依赖内部 contract。

### FR-03 — Access and License Enforcement

要求：每次采集使用审核通过的 `access_level`、`license_policy`、retention class 和 allowed
content scope。公开网页不等于允许批量保存全文：

- `PUBLIC_FULLTEXT` 只有在明确允许时保存全文；
- `PUBLIC_SUMMARY` 只保存公开摘要及允许元数据；
- `SUBSCRIPTION_REQUIRED`、`LINK_ONLY`、`BLOCKED` 可作为线索状态，但不得伪装为 full text；
- `LICENSED` 只按合同允许范围保存和处理；
- Bloomberg / WSJ 未授权时，完整正文采集不是成功条件；
- 不绕过付费墙、登录、captcha、robots 或访问控制；
- 付费或受版权保护内容只保存授权范围内容或引用。

验收方式：fixtures 覆盖全部 access level 映射；安全测试证明受限内容不会进入 payload，禁止
路径不会发起 fallback。

### FR-04 — Cursor, Watermark and Limited Backfill

要求：adapter 明确 cursor/watermark 类型、初始状态、单调 successor 和时间水位。所有
checkpoint 继续使用 SPEC-0003 的 RawItem/cursor 原子事务。

仅允许 provider 合同明确支持、用户批准且有固定上限的 backfill window；无法直接恢复时
必须可见失败，不得自动扩大时间窗、切换 provider 或实现通用 Historical Backfill 框架。

验收方式：cursor resume、分页 checkpoint、旧 watermark、rollback、重启恢复和受限 backfill
测试；失败时 cursor 不推进。

### FR-05 — Retry, Rate Limit and Failure Visibility

要求：provider-specific 错误映射到 SPEC-0003 的稳定错误分类，统一框架负责 retry/backoff。
429 使用合法 Retry-After；auth/forbidden/not-found/contract/config 错误不得盲目 retry。
所有错误必须脱敏且在 CollectionRun 可见。

验收方式：fixture/transport fault injection 覆盖 timeout、network、429、5xx、auth、forbidden、
not found、invalid payload 和未知异常；断言 run 状态、retry 决策和日志脱敏。

### FR-06 — Idempotency and RawItem Persistence

要求：stable external ID 优先形成确定性幂等身份；provider 无稳定 ID 时，fallback 必须在
文档中定义为来源范围内稳定、可测试且不依赖随机值。RawItem 必须关联当前 CollectionRun，
且只保存许可允许的最小 payload 或引用。

本 SPEC 的 duplicate protection 只保证重复 poll/retry 不产生不受控副作用；ContentItem
normalization 与 dedup 仍属于 SPEC-0006。

验收方式：重复 poll、retry、cursor replay 和有限 backfill 测试证明幂等，RawItem 来源/run/
account 关联正确，无孤立数据。

### FR-07 — Time Semantics

要求：严格区分来源 `published_at`、来源 `source_updated_at`、系统 `first_seen_at` 和本次
`fetched_at`。缺失值保持 null，不猜测；provider 时区必须明确并转换为 UTC。

验收方式：fixture 覆盖完整时间、缺失时间、非 UTC offset、更新记录和重复获取。

### FR-08 — Verification Evidence Gate

要求：真实 smoke test 只能在用户确认 provider、授权与接入政策后运行。结果必须记录日期、
endpoint 类别、授权状态、内容范围、请求数、RawItem/CollectionRun/cursor 结果和任何限制；
不得记录秘密或未授权正文。

验收方式：实施 PR 的 Delivery Report 提供真实证据；未授权或无法访问时必须明确 BLOCKED，
只能报告 contract/fixture 测试，不能声称真实接入通过。

## 9. 非功能需求

- 可靠性：重复 poll、retry 和重启保持幂等；cursor 只在 RawItem 安全持久化后推进。
- 性能：轮询间隔、batch 和 backfill 有界，遵守 provider rate limit。
- 安全：外部数据不可信；无登录/付费墙/captcha 绕过；秘密、cursor、query 和 payload 脱敏。
- 合规：access/license/retention 决定可获取与保存范围；blocked 必须 fail closed。
- 可替换性：删除该 adapter 不改变 runner 或 downstream contract。
- 可观测性：每次真实运行有 CollectionRun，失败不能表现为“没有新消息”。
- 实时性：只声明审核后的 Near Real-time、Standard 或 Periodic tier，不承诺 provider 未保证的 SLA。

## 13. 错误处理

| Error Code | 条件 | Retry | 运维表现 |
|---|---|---|---|
| `COLLECTION_TIMEOUT` | provider 请求超时 | 是 | 统一 backoff，cursor 不推进 |
| `COLLECTION_NETWORK` | 临时网络失败 | 是 | 统一 backoff |
| `COLLECTION_RATE_LIMITED` | 429/明确限流 | 是 | 合法 Retry-After 或 capped backoff |
| `COLLECTION_UPSTREAM_5XX` | provider 5xx | 是 | 统一 backoff |
| `COLLECTION_UPSTREAM_RETRYABLE` | contract 明确的临时错误 | 是 | 统一 backoff |
| `COLLECTION_AUTH` | 缺失或失效授权 | 否 | failed；等待人工确认 |
| `COLLECTION_FORBIDDEN` | 401/403、robots/terms/access 阻塞 | 否 | failed/blocked；不得 fallback |
| `COLLECTION_NOT_FOUND` | endpoint/feed 404/410 | 否 | failed；人工核验 |
| `COLLECTION_CONTRACT_INVALID` | payload/cursor/envelope 不符合合同 | 否 | failed；开发错误可见 |
| `COLLECTION_CONFIG_INVALID` | provider 未确认、adapter 未注册或配置缺失 | 否 | 不运行或 failed |
| `COLLECTION_UNKNOWN` | 未分类异常 | 否 | failed；不得盲目 retry |

其余数据库、lock、cancelled、stale-run 分类沿用 SPEC-0003。错误正文必须长度受限并脱敏。

## 14. Migration and Rollback

- 升级：无数据库迁移；未来实现只增加一个可移除 adapter、注册、fixture、配置模板和测试。
- 回滚：先禁用对应 Source/SourceAccount 并停止其任务，再移除 adapter 注册和配置；既有
  RawItem、CollectionRun 和 cursor 保留用于审计。
- 数据兼容：只写既有 Phase 1 表和字段，不改变 schema。
- 备份要求：无新 schema；真实或受限 payload 不得进入 Git、测试 fixture 或 Review ZIP。
